# dsh-claude-style 0.20.3 — заплатка «меньше лишних записей»

Собран из рабочей копии темы (ветка perf/skin-writes). Оригинал темы не удалён:
в профиле desktop остаётся установленная 0.20.3, пока вы её не замените.

## Что внутри

Одна правка поведения, три места, все — про лишние записи в DOM на каждом
проходе планировщика темы (а он ходит по всем фичам на каждое изменение
содержимого, то есть на каждом кадре стрима):

1. features/turn-nav/turn-nav.ts — метки рейла перестраивались (по одной
   вставке и одному удалению узла на виток) даже когда набор витков не менялся.
   Теперь при том же числе витков правится только атрибут «не загружен».
   Замер: 36 вставок + 35 удалений за один ответ → 9 + 8 (остальное — реальные
   добавления витков).
2. features/context-stats/meter-ring.ts — `data-dsh-claude-meter-hidden`
   писался безусловно на каждом проходе (36 записей на ответ, каждая инвалидирует
   поддерево). Заменено на setAttributeIfChanged: 36 → 0 лишних.
3. features/effort/slider.ts — четыре aria-атрибута ползунка усилий писались
   на каждом проходе (по 10-13 раз на ответ). Теперь только при изменении.

## Чего это не лечит (важно)

Стрим остаётся тяжёлым, и тяжесть даёт не тема, а пересчёт стилей хоста:
403–427 мс на один ответ, ~53 000 элементов пересчитано, из причин инвалидации
2688 — `Affected by :has()` в CSS хоста (в asar хоста 170 вхождений `:has(`).
Краска (paint) при этом 6–8 мс. Тема тратит на свой JS около 5 % времени.

Поэтому замер до/после на трёх прогонах по три ответа разницы в кадрах не
показал (медиана sampled 683 мс → 651 мс, шум прогонов ±30 %). Это гигиена,
а не ускорение: убраны лишние инвалидации, которые могли давать мигание рейла.

## Установка

```bash
dsh plugin add "./extras/claude-style-perf/dsh-claude-style-0.20.3.tgz"
```
После установки перезапустить приложение DeepSeek Harness. Откат — поставить
0.20.3 из npm/marketplace заново.
